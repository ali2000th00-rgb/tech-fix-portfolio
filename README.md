# TECH FIX — Software & IT Solutions

موقع Portfolio عربي RTL لفني سوفتوير ودعم فني. مبني بـ HTML5 وCSS3 وJavaScript دون إطار عمل أو حزم وقت تشغيل؛ لا يحتاج إلى `npm install` أو عملية build. أزيلت الاعتمادات البرمجية والخطوط الخارجية من الواجهة، وأصبحت الأيقونات محلية.

## هيكل المشروع

```text
tech-fix-portfolio/
├── index.html                   # الصفحة والأقسام والبيانات
├── styles.css                   # التصميم المتجاوب والثيمات والحركات
├── icons.js                     # عارض أيقونات SVG محلي بلا مكتبات خارجية
├── app.js                       # القائمة والفلترة والثيم والتحقق من النموذج
├── assets/                      # favicon وصورة المشاركة
├── robots.txt                   # تعليمات فهرسة عامة دون نطاق وهمي
├── sitemap.xml.template         # قالب يُحوّل إلى sitemap.xml بعد تثبيت النطاق
├── _headers                     # ترويسات Netlify / Cloudflare Pages
├── vercel.json                  # ترويسات Vercel
├── .htaccess                    # ترويسات Apache
├── nginx-security-headers.conf  # مقطع إعدادات Nginx
├── SECURITY-AUDIT.md            # ملخص المراجعة وحدود الحماية
└── README.md
```

## التشغيل المحلي

1. فك ضغط ملف ZIP.
2. افتح `index.html` مباشرة، أو شغّل خادماً محلياً:

   ```bash
   python -m http.server 8000
   ```

   ثم افتح `http://localhost:8000`.

## التعديلات قبل النشر

- الاسم والوصف: عدّل `index.html` في قسم Hero ووسوم metadata.
- البريد والهاتف: عدّل روابط `mailto:` و`tel:` في قسم التواصل وعنوان البريد المستعمل في تجهيز الرسالة داخل `app.js`.
- WhatsApp: الرابط الحالي يفترض رقم السودان `+249117388030` بعد تحويل الرقم المحلي المقدم `0117388030`. تحقّق من الرقم ورمز البلد قبل النشر.
- GitHub وLinkedIn: استبدل `your-username` و`your-profile` بروابط صحيحة أو احذف الرابطين.
- المشاريع الستة ونماذج آراء العملاء: محتوى توضيحي تجريبي، وليس سجلاً لأعمال أو مراجعات حقيقية.
- الخبرة 3 سنوات مبنية على المعلومة التي قدمها صاحب الموقع. لا تغيّر الإحصاءات إلا إلى أرقام موثقة.
- النطاق: لا يوجد نطاق حقيقي ضمن البيانات المقدمة. بعد اختيار النطاق، أضف `canonical` و`og:url`، وضع رابط HTTPS مطلقاً لصورة Open Graph، ثم حوّل `sitemap.xml.template` إلى `sitemap.xml` بتعديل `YOUR-REAL-DOMAIN`. لا تنشر القالب كما هو.

## نموذج التواصل وحدود الحماية

النموذج يتحقق من المدخلات في المتصفح، ويقصر نوع الخدمة على عناصر القائمة ويستخدم حقل honeypot كإشارة بسيطة. عند الإرسال يفتح رابط `mailto:` ولا يرسل البيانات إلى خادم ولا يحفظها. قد لا يعمل ذلك إن لم يكن لدى الزائر تطبيق بريد مضبوط. التحقق داخل المتصفح قابل للتجاوز؛ لا يعتبر حدّاً أمنياً لخادم.

إذا أردت استقبال الرسائل مباشرة، أضف Backend منفصلاً أو استخدم خدمة نماذج موثوقة. يجب أن ينفذ الخادم التحقق من المدخلات، وحدود حجم الطلب، وتحديد معدل الإرسال، ومكافحة Spam، وسياسة الخصوصية، وتسجيل الأخطاء دون الاحتفاظ ببيانات أكثر من اللازم. لا تضع مفاتيح API السرية في ملفات الواجهة.

## ترويسات الأمان

اختر ملف إعداد واحداً بحسب الاستضافة: `_headers` لـ Netlify/Cloudflare Pages، أو `vercel.json` لـ Vercel، أو `.htaccess` لـ Apache، أو `nginx-security-headers.conf` لـ Nginx. لا حاجة إلى نسخ كل الإعدادات إلى الاستضافة نفسها. تفعّل الإعدادات CSP صارمة بلا `unsafe-inline` وتمنع التضمين في إطارات خارجية وتضيف سياسات للمتصفح. فعّل HTTPS ثم تحقق من الترويسات فعلياً؛ فتح HTML من القرص أو خادم محلي بسيط لا يطبق ترويسات الاستضافة.

## الفحص الأمني

شغّل الفحوص المحلية من داخل مجلد المشروع:

```bash
node --check app.js
node --check icons.js
python3 scripts/security-smoke-test.py
```

راجع `SECURITY-AUDIT.md` لنتائج المراجعة وحدودها. هذه مراجعة مصدر وإعدادات وفحوص محلية، وليست اختبار اختراق أو تدقيقاً لخادم منشور.
